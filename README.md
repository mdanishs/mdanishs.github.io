# mdanishs.com

Personal site of Mohammad Danish Siddiqui — senior frontend engineer, CDI
Certified Resume Analyst, founder of [HireDoc](https://hiredoc.co).

Jekyll on GitHub Pages. No build step, no framework, no JS dependencies — the
whole site is one stylesheet plus two web fonts.

## Editing content

Most changes don't require touching HTML:

| What you want to change | File |
| --- | --- |
| Name, tagline, nav, social links, HireDoc URLs, headline numbers | `_config.yml` |
| Roles and impact bullets on `/experience/` | `_data/experience.yml` |
| FAQ on `/resume-help/` (also feeds FAQ structured data) | `_data/faq.yml` |

The numbers in `_config.yml` under `brand:` (years of experience, resumes
reviewed) are interpolated into page copy, so updating them there updates them
everywhere.

## SEO and AEO

- `_includes/head.html` — titles, descriptions, canonicals, Open Graph, Twitter
  cards. `robots` includes `max-snippet:-1` so answer engines can quote full
  passages.
- `_includes/schema.html` — all JSON-LD, emitted as one `@graph` (Person,
  Organization, WebSite, WebPage, BreadcrumbList, plus FAQPage / Product /
  BlogPosting where relevant). Values come from `_config.yml` and `_data/`, so
  the structured data can't drift from the visible copy.
- `robots.txt` — explicitly allows search crawlers and answer-engine crawlers
  (GPTBot, OAI-SearchBot, ClaudeBot, PerplexityBot, Google-Extended, etc.).
- `llms.txt` — a plain-text summary of the site for LLMs, at `/llms.txt`.
- `sitemap.xml` — generated by `jekyll-sitemap`.

Pages opt into extra structured data through front matter: `faq: true`,
`offers: true`, `profile-page: true`.

### Adding an FAQ entry

Add to `_data/faq.yml`. It renders on `/resume-help/` and enters the FAQPage
schema automatically. Write the answer so it makes sense with no surrounding
context — lead with the direct answer, name entities explicitly, keep it to
40–90 words.

## Analytics

Uncomment `gtag:` in `_config.yml` and paste the GA4 Measurement ID
(`G-XXXXXXXXXX`, from Admin → Data streams → Web). Nothing loads while it is
unset, so local builds and forks send no data.

On top of GA4's automatic pageviews, every call to action carries a
`data-cta="..."` attribute and fires a **`cta_click`** event with that label.
GA4's enhanced measurement already logs outbound clicks, but every conversion
here is outbound — quiz, HireDoc, LinkedIn — so without labels they collapse
into one bucket. The labels are what make per-CTA click-through comparable.

To see them: **Reports → Engagement → Events → `cta_click`**. Add `cta` as a
custom dimension (Admin → Custom definitions → Create custom dimension, event
scope, parameter `cta`) to break the number down per button. Dimensions only
apply going forward, so create it before you start caring about the data.

To track a new button, add `data-cta="some-label"` to it — no other wiring.

## Running locally

```sh
bundle install
bundle exec jekyll serve
```

Then open <http://localhost:4000>.

## Images

| File | Purpose |
| --- | --- |
| `img/danish.jpg` | Portrait used in the hero and nav, and as the `Person` image in schema |
| `img/og-card.png` | 1200×630 social share card |
| `img/favicon.png` | Favicon |

`og-card.png` and `favicon.png` are generated. After replacing `img/danish.jpg`
(or changing the card headline), regenerate them:

```sh
pip install Pillow
python3 tools/make-images.py
```

The script center-crops whatever it finds at `img/danish.jpg`, so the portrait
does not need to be square.
